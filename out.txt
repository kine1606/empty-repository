## 📊 Comparison: Static vs Dynamic Linking

| Aspect | Static Library | Dynamic Library |
|--------|---------------|-----------------|
| **File Extension** | `.a` or `.la` | `.so` or `.la` |
| **Build Flag** | Standard compilation | `-fPIC`, `-shared` |
| **Link Time** | Code copied into executable | Reference recorded |
| **Executable Size** | Larger | Smaller |
| **Runtime Dependency** | None | Requires .so file |
| **Update Library** | Must recompile app | Replace .so file |
| **Memory Usage** | Per-process | Shared across processes |
| **Use Case** | Self-contained binaries | Shared system libraries |

## 🐛 Common Issues & Solutions

### Issue 1: `undefined reference to`
**Cause:** Link order wrong  
**Fix:** Put libraries AFTER source files in LDADD

### Issue 2: `cannot find -lfoo`
**Cause:** Library path missing  
**Fix:** Use full path: `$(top_builddir)/lib/libfoo.la`

### Issue 3: `error while loading shared libraries`
**Cause:** Runtime linker can't find .so  
**Fix:** Add RPATH: `-Wl,-rpath,'$$ORIGIN/../lib/.libs'`

### Issue 4: `gtest/gtest.h: No such file or directory`
**Cause:** Include path wrong  
**Fix:** Add `-I$(top_srcdir)/vendor/googletest/googletest/include`

See [TROUBLESHOOTING.md](TROUBLESHOOTING.md) for complete list.

## Linking Quick Reference

### Static Library
```makefile
# lib/Makefile.am
lib_LTLIBRARIES = libcalc.la
libcalc_la_SOURCES = calculator.cpp

# app/Makefile.am
calculator_LDADD = $(top_builddir)/lib/libcalc.la
```

**Characteristics:**
- Extension: `.a`
- No runtime dependency
- Larger executable
- Code copied at link time

### Dynamic Library
```makefile
# lib/Makefile.am
lib_LTLIBRARIES = liblogger.la
liblogger_la_LDFLAGS = -version-info 1:0:0

# app/Makefile.am
logger_app_LDFLAGS = -Wl,-rpath,'$$ORIGIN/../lib/.libs'
logger_app_LDADD = $(top_builddir)/lib/liblogger.la
```

**Characteristics:**
- Extension: `.so`
- Runtime dependency exists
- Smaller executable
- Code loaded at runtime

## Google Test Quick Reference

### Test Structure
```cpp
#include <gtest/gtest.h>

// Simple test
TEST(SuiteName, TestName) {
    EXPECT_EQ(2 + 2, 4);
    ASSERT_TRUE(some_condition);
}

// Test with fixture
class MyTest : public ::testing::Test {
protected:
    void SetUp() override { /* setup */ }
    void TearDown() override { /* teardown */ }
    MyClass obj;
};

TEST_F(MyTest, DoesSomething) {
    EXPECT_EQ(obj.method(), expected);
}

// Parameterized test
class ParamTest : public ::testing::TestWithParam<int> {};

TEST_P(ParamTest, HandlesParam) {
    EXPECT_GT(GetParam(), 0);
}

INSTANTIATE_TEST_CASE_P(
    Instances,
    ParamTest,
    ::testing::Values(1, 2, 3)
);
```

## Common Errors & Quick Fixes

| Error | Quick Fix |
|-------|-----------|
| `undefined reference to` | Check link order: sources BEFORE libraries |
| `cannot find -lfoo` | Use full path: `$(top_builddir)/lib/libfoo.la` |
| `error while loading shared libraries` | Add RPATH or export `LD_LIBRARY_PATH` |
| `gtest/gtest.h: No such file or directory` | Add `-I$(top_srcdir)/vendor/googletest/googletest/include` |
| `automake: error: no Makefile.am` | Create Makefile.am for each directory |
| `libtool: not found` | `LT_PREREQ([2.4])` and `LT_INIT` in configure.ac |

## pkg-config Quick Reference

### Create .pc file
```bash
prefix=/usr/local
exec_prefix=${prefix}
libdir=${exec_prefix}/lib
includedir=${prefix}/include

Name: libcalc
Description: Calculator library
Version: 1.0.0
Libs: -L${libdir} -lcalc
Cflags: -I${includedir}
```

### Usage
```bash
# Set search path
export PKG_CONFIG_PATH=/path/to/lib/pkgconfig

# Query
pkg-config --cflags libcalc
pkg-config --libs libcalc
pkg-config --modversion libcalc
```

## Library Versioning

### -version-info current:revision:age
- **current**: Increment if interface changed
- **revision**: Increment if source changed (reset to 0 if current changed)
- **age**: Increment if interfaces added, reset to 0 if removed

### Example
```makefile
libfoo_la_LDFLAGS = -version-info 3:0:1
# Interface version 3, revision 0, age 1
# Compatible with versions 2, 3
```

## 📚 What, Why, How

### What is Autotools?

**GNU Autotools** (GNU Build System) is a suite of programming tools designed to assist in making source code packages portable across many Unix-like systems.

**Tools:**
- **Autoconf** (`configure.ac` → `configure`): Generates platform detection scripts
- **Automake** (`Makefile.am` → `Makefile.in`): Generates portable Makefiles
- **Libtool** (`*.la` files): Manages static/shared libraries portably

### Why Autotools?

| Advantage | Explanation |
|-----------|-------------|
| **Portability** | Works on any Unix-like system without modification |
| **Platform Detection** | Automatically finds compilers, libraries, headers |
| **Standard Interface** | `./configure && make && make install` is universal |
| **Dependency Management** | Handles complex build dependencies |
| **Distribution** | `make dist` creates release tarballs |

### How the Build Pipeline Works

```
┌─────────────────────────────────────────────────────────────────┐
│                    AUTOTOOLS BUILD PIPELINE                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Source Files        Autotools           Build Artifacts        │
│  ────────────        ─────────           ───────────────        │
│                                                                  │
│  configure.ac  ──┐                                              │
│                  ├──► autoreconf -fi ──► configure              │
│  Makefile.am  ──┘                                              │
│                           │                                     │
│                           ▼                                     │
│                    ./configure       ──► Makefile               │
│                           │                                     │
│                           ▼                                     │
│                    make              ──► binaries, libraries    │
│                           │                                     │
│                           ▼                                     │
│                    make check        ──► run tests              │
│                           │                                     │
│                           ▼                                     │
│                    make install      ──► /usr/local/*           │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### Static vs Dynamic Libraries

```
┌──────────────────────────────────────────────────────────────┐
│                    STATIC LIBRARY (.a / .la)                  │
├──────────────────────────────────────────────────────────────┤
│                                                               │
│  Source → Object Files → [ar] → libfoo.a                     │
│                                    ↓                          │
│  Link time: COPY code into executable                         │
│                                                               │
│  ✅ Fast loading (no runtime lookup)                          │
│  ✅ No runtime dependency                                     │
│  ❌ Larger executables                                        │
│  ❌ Must recompile to update library                          │
│                                                               │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│                   DYNAMIC LIBRARY (.so / .la)                 │
├──────────────────────────────────────────────────────────────┤
│                                                               │
│  Source → Object Files (-fPIC) → [ld -shared] → libfoo.so    │
│                                           ↓                   │
│  Link time: RECORD dependency                                 │
│  Run time: LOAD library from disk                             │
│                                                               │
│  ✅ Smaller executables                                       │
│  ✅ Update library without recompiling apps                   │
│  ✅ Share memory across processes                             │
│  ❌ Slower loading (runtime resolution)                       │
│  ❌ Dependency hell (missing .so files)                       │
│                                                               │
└──────────────────────────────────────────────────────────────┘
```

### Linkage Process Deep Dive

```
Compilation:  source.cpp ──► object.o
              (g++ -c)

Static Link:  main.o + libfoo.a ──► executable
              (g++ -o, copies code from .a into executable)

Dynamic Link: main.o + libfoo.so ──► executable
              (g++ -o, records "needs libfoo.so")
              
              At runtime:
              executable ──► loader finds libfoo.so
                           ──► maps into memory
                           ──► resolves symbols
```

**Key Linker Flags:**
- `-I/path`: Add include directory for headers
- `-L/path`: Add library search directory
- `-lfoo`: Link against `libfoo.so` or `libfoo.a`
- `-Wl,-rpath,/path`: Embed runtime library path in executable
- `-fPIC`: Position Independent Code (required for shared libs)

### Common Autotools Errors

| Error | Cause | Fix |
|-------|-------|-----|
| `configure.ac: file not found` | Missing `configure.ac` | Create file or run from correct directory |
| `automake: error: no Makefile.am` | Missing `Makefile.am` | Create file for each directory |
| `libtool: not found` | Libtool not installed | `sudo yum install libtool` |
| `undefined reference to` | Link order wrong | Put libraries AFTER object files |
| `cannot find -lfoo` | Library path missing | Add `-L/path` or set `LD_LIBRARY_PATH` |
| `error while loading shared libraries` | .so not found at runtime | Use `-Wl,-rpath` or export `LD_LIBRARY_PATH` |

# Troubleshooting Guide

## Common Autotools Errors and Fixes

### 1. `autoreconf: error: configure.ac: file not found`

**Cause:** Missing `configure.ac` or wrong directory.

**Fix:**
```bash
# Check you're in the right directory
ls configure.ac

# Or create the file
touch configure.ac
```

---

### 2. `automake: error: no Makefile.am`

**Cause:** Missing `Makefile.am` in a directory listed in `AC_CONFIG_FILES`.

**Fix:**
```bash
# Create Makefile.am for each directory in AC_CONFIG_FILES
touch lib/Makefile.am
touch app/Makefile.am
```

---

### 3. `libtool: not found` or `LT_INIT: not found`

**Cause:** Libtool not installed or not in PATH.

**Fix:**
```bash
# Install libtool
sudo yum install libtool libtool-ltdl-devel

# Or on Debian/Ubuntu
sudo apt-get install libtool

# Verify installation
libtool --version
```

---

### 4. `undefined reference to Calculator::add(int, int)`

**Cause:** Link order wrong - libraries must come AFTER object files.

**Fix in Makefile.am:**
```makefile
# WRONG (library before sources)
calculator_LDADD = $(top_builddir)/lib/libcalc.la
calculator_SOURCES = main.cpp

# CORRECT (sources before library in the link command)
calculator_SOURCES = main.cpp
calculator_LDADD = $(top_builddir)/lib/libcalc.la
```

---

### 5. `error: cannot find -lcalc`

**Cause:** Library search path not specified.

**Fix in Makefile.am:**
```makefile
calculator_LDADD = \
    -L$(top_builddir)/lib \
    $(top_builddir)/lib/libcalc.la
```

Or use the full path (preferred with libtool):
```makefile
calculator_LDADD = $(top_builddir)/lib/libcalc.la
```

---

### 6. `error while loading shared libraries: libfoo.so: cannot open shared object file`

**Cause:** Runtime linker can't find the shared library.

**Fixes (choose one):**

**Option A: Use RPATH (recommended for development)**
```makefile
app_LDFLAGS = -Wl,-rpath,'$$ORIGIN/../lib/.libs'
```

**Option B: Set LD_LIBRARY_PATH**
```bash
export LD_LIBRARY_PATH=/path/to/lib:$LD_LIBRARY_PATH
./app/myapp
```

**Option C: Install library to system directory**
```bash
sudo make install
sudo ldconfig
```

---

### 7. `configure: error: C++ compiler cannot create executables`

**Cause:** Compiler not found or broken.

**Fix:**
```bash
# Check compiler
which g++
g++ --version

# Set compiler explicitly if needed
export CXX=g++
export CC=gcc
./configure
```

---

### 8. `aclocal: error: aclocal not found`

**Cause:** Automake not installed.

**Fix:**
```bash
# Install automake
sudo yum install automake autoconf

# Verify
aclocal --version
automake --version
```

---

### 9. `Makefile.am: error: required file 'build-aux/compile' not found`

**Cause:** Autotools auxiliary scripts missing.

**Fix:**
```bash
# Create build-aux directory and regenerate
mkdir -p build-aux
autoreconf -fi
```

---

### 10. `libtool: warning: library 'libfoo.la' was moved`

**Cause:** Library was relocated after being built.

**Fix:**
```bash
# Clean and rebuild
make clean
make
```

## Understanding Autotools Output

### What `autoreconf -fi` does:
```
aclocal     → Collects m4 macros from installed packages
autoconf    → Generates configure script from configure.ac
autoheader  → Generates config.h.in template
automake    → Generates Makefile.in from Makefile.am
libtoolize  → Installs libtool support files
```

### What `./configure` does:
```
1. Checks for programs (compiler, linker, etc.)
2. Checks for libraries and headers
3. Detects platform-specific features
4. Generates Makefile from Makefile.in
5. Generates config.h with detected settings
```

### What `make` does:
```
1. Compiles source files to object files
2. Creates libraries (.a, .so)
3. Links executables
4. Handles dependencies automatically
```

## Google Test Specific Issues

### `gtest/gtest.h: No such file or directory`

**Fix:** Ensure include path is correct in Makefile.am:
```makefile
test_program_CPPFLAGS = -I$(top_srcdir)/vendor/googletest/googletest/include
```

### `undefined reference to testing::Test`

**Cause:** Google Test library not linked.

**Fix:**
```makefile
test_program_LDADD = \
    $(top_builddir)/vendor/googletest/libgtest.la \
    $(top_builddir)/vendor/googletest/libgtest_main.la
```

### `make check` doesn't run tests

**Fix:** Ensure TESTS is set:
```makefile
TESTS = test_myprogram
```

## Best Practices

### 1. Always use libtool for libraries
```makefile
# GOOD
lib_LTLIBRARIES = libfoo.la

# BAD (don't use ar directly)
noinst_LIBRARIES = libfoo.a
```

### 2. Use top_builddir and top_srcdir
```makefile
# GOOD (works from any subdirectory)
calculator_LDADD = $(top_builddir)/lib/libcalc.la

# BAD (breaks if run from subdirectory)
calculator_LDADD = ../lib/libcalc.la
```

### 3. Put libraries after object files
```makefile
# CORRECT order
myapp_SOURCES = main.cpp utils.cpp
myapp_LDADD = libfoo.la

# WRONG order (causes undefined reference errors)
myapp_LDADD = libfoo.la
myapp_SOURCES = main.cpp utils.cpp
```

### 4. Use -version-info for shared libraries
```makefile
libfoo_la_LDFLAGS = -version-info 1:0:0
```

### 5. Clean build when switching branches or making major changes
```bash
make distclean
autoreconf -fi
./configure
make
```

# Script to download and extract Google Test
# Run this before building level-4-gtest or level-5-complete

set -e

VENDOR_DIR="$SCRIPT_DIR/vendor"
GTEST_VERSION="1.14.0"

echo "=== Google Test Download Script ==="
echo ""
echo "This script will download Google Test $GTEST_VERSION"
echo "Location: $VENDOR_DIR/googletest"
echo ""

# Create vendor directory if it doesn't exist
mkdir -p "$VENDOR_DIR"

# Check if googletest already exists
if [ -d "$VENDOR_DIR/googletest" ]; then
    echo "Google Test already exists in $VENDOR_DIR/googletest"
    echo "To re-download, remove it first:"
    echo "  rm -rf $VENDOR_DIR/googletest"
    exit 0

# Download Google Test
echo "Downloading Google Test $GTEST_VERSION..."
cd "$VENDOR_DIR"

# Try wget first, fall back to curl
if command -v wget &> /dev/null; then
    wget -q "https://github.com/google/googletest/archive/refs/tags/v${GTEST_VERSION}.tar.gz" \
         -O "gtest-${GTEST_VERSION}.tar.gz"

#include "logger.h"
#include <iostream>
#include <ctime>

void Logger::setLevel(Level level) {
    m_level = level;
}

const char* Logger::levelToString(Level level) {
    switch (level) {
        case DEBUG:   return "DEBUG";
        case INFO:    return "INFO";
        case WARNING: return "WARNING";
        case ERROR:   return "ERROR";
        default:      return "UNKNOWN";
    }
}

void Logger::log(Level level, const std::string& message) {
    if (level >= m_level) {
        // Get current time
        std::time_t now = std::time(nullptr);
        char time_buf[20];
        std::strftime(time_buf, sizeof(time_buf), "%Y-%m-%d %H:%M:%S", std::localtime(&now));
        
        std::cout << "[" << time_buf << "] "
                  << "[" << levelToString(level) << "] "
                  << message << std::endl;
    }
}

void Logger::debug(const std::string& msg) { log(DEBUG, msg); }
void Logger::info(const std::string& msg) { log(INFO, msg); }
void Logger::warning(const std::string& msg) { log(WARNING, msg); }
void Logger::error(const std::string& msg) { log(ERROR, msg); }

        return 0.0;
